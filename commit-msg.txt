[SEC-10] Fix: No audit or activity logging anywhere in the application

Found that the app had absolutely no logging of any security
relevant events. No record of who logged in or when, no record of
failed login attempts, no record of admin actions being performed.
Confirmed this by checking the project folder directly and finding
no logs folder or log files of any kind existed anywhere.

This matters because if any real attack happened, including any of
the vulnerabilities found and fixed earlier in this project, there
would be zero trace of it afterward, making investigation or
incident response completely impossible.

Fixed by installing winston and creating a centralized logger
utility that writes structured, timestamped JSON logs to both the
console and a logs/security.log file. Wired this into the auth
controller to log successful registrations, successful logins, and
failed login attempts with the reason for failure. Also wired it
into the adminMiddleware so every single admin protected action is
logged with the acting users id, email, the route accessed, and the
HTTP method used.

Was careful to only ever log identifying and contextual information
such as user id, email, ip address, and route, and never log
passwords, tokens, or any other sensitive field, to avoid creating
a new sensitive data exposure risk through the logs themselves.
Added logs folder to gitignore since log files should not be
committed to the repository.

Retested after the fix by triggering a successful login, a failed
login, and an admin protected request, then checking the log file
and confirming all three events were correctly captured with
appropriate detail and no sensitive data present.
