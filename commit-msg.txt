[SEC-11] Fix: Broken function-level authorization on product management routes

Found that the public product routes only checked whether a user
was logged in, not whether they were an admin, even though the
exact same product create, update, and delete functionality was
correctly restricted to admins only through a separate admin
prefixed route using the same controller. This meant there were two
paths to the same functionality, one properly secured and one
completely open to any registered user.

Proved this by logging in as a normal, non-admin test account and
successfully deleting a real product from the live database using
only the unprotected route, with no admin access at all. Confirmed
the product was actually gone afterward, not just a fake success
response.

Fixed by adding adminMiddleware alongside the existing
authorizationMiddleware on the create, update, and delete product
routes, while intentionally leaving the read only routes, get all
products and get product by id, public and unauthenticated, since
browsing the store should not require being logged in.

Retested after the fix using the exact same non-admin account and a
different existing product, and confirmed the request is now
correctly blocked with a forbidden not admin response instead of
succeeding.
