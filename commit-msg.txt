[SEC-07] Fix: No session revocation and excessively long JWT lifetime

Found two related problems with session handling. First, there was
no logout route wired up at all in the router, even though a logout
function existed in the controller, so users had no way to end
their session early through the app. Second, JWT tokens were valid
for 30 days with no revocation mechanism of any kind, meaning a
stolen token would remain fully usable for a full month regardless
of what the legitimate user did.

Proved this by logging in, calling logout, and then reusing the
exact same token again on a protected route, which succeeded
completely, showing logout had no real effect even after the route
was added.

Fixed by creating a simple in memory token blacklist. The logout
endpoint now adds the users current token to this blacklist, and
the auth middleware checks every incoming token against it before
verifying the token normally, rejecting any token that has been
explicitly logged out. Also reduced the JWT expiry from 30 days
down to 1 hour, to shrink the exposure window if a token is ever
stolen. Noted in code comments that a production deployment with
multiple servers would need a shared store like Redis instead of
in memory storage for this to work correctly across instances.

Retested after the fix by logging in, calling logout, then
attempting to reuse the same token again, and confirmed it is now
correctly rejected with a token has been revoked message.
