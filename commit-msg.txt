[SEC-16] Add input sanitization for product fields (XSS defense-in-depth)

Tested the product name and description fields for stored cross
site scripting by submitting a script tag payload through the
product creation endpoint. The payload was accepted and stored
unsanitized in the database. When viewed on the actual frontend,
no script execution occurred, confirming React's default behavior
of escaping text content rather than interpreting it as HTML, so
this was not currently exploitable as a live vulnerability.

However, storing unsanitized HTML and script content in the
database is not defense in depth best practice. If any future
frontend change introduced dangerouslySetInnerHTML or a different
rendering path for these fields, the already stored payloads would
become immediately exploitable without needing to be resubmitted.

Added the sanitize-html library and applied it to the name,
category, and description fields on both product creation and
update, stripping all HTML tags and attributes before the data is
ever stored, regardless of what the frontend currently does with
it.

Tested with a fully malicious payload, which was correctly
stripped down to an empty string and rejected by the required
field validation as expected. Also tested with a realistic mixed
payload containing both legitimate text and a script tag, and
confirmed the legitimate text was preserved while only the
malicious script content was removed.
