Add password complexity requirements and prepare for reuse prevention

Strengthened the password validation schema to require a minimum
of 8 characters, at least one uppercase letter, one lowercase
letter, one number, and one special character, replacing the
previous minimum of just 6 characters with no complexity rules at
all. This satisfies the coursework requirement for a robust
password policy.

Added a passwordHistory field to the user schema and type
definitions, storing an array of previous password hashes, marked
select false so it is hidden by default from normal queries. This
lays the groundwork for password reuse prevention on password
change, preventing users from cycling back to a recently used
password.
