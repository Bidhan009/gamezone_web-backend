[SEC-05] Fix: Remove hardcoded JWT secret fallback

Found that if the JWT_SECRET environment variable was ever missing
(forgotten .env file, misconfigured deployment, container without
the var set), the app would silently fall back to the literal
string default as the signing secret, and still start up normally
with no warning.

Proved this was exploitable by temporarily removing JWT_SECRET from
my own .env, then manually forging a JWT token outside the app
using nothing but the known fallback value default and a real
users ID copied from the database. Used that forged token against
a protected endpoint and successfully impersonated that real user
with zero password and zero legitimate login.

Fixed by making config/index.ts throw a fatal error and refuse to
start the application entirely if JWT_SECRET is not explicitly set
in the environment, instead of silently falling back to an insecure
default. Also generated and set a proper long random secret using
Node cryptos randomBytes instead of a short guessable string.

Retested after the fix in two parts. First, confirmed the app now
refuses to start at all when JWT_SECRET is missing, showing a clear
fatal error message. Second, confirmed my previously forged token
(signed with the old fallback default) is now rejected with an
invalid signature error once the real secret is restored, since it
no longer matches.
