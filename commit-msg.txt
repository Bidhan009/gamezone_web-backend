Add CAPTCHA verification to registration and login endpoints

Implemented Google reCAPTCHA v2 verification on the register and
login endpoints, satisfying the coursework requirement for
brute-force and bot protection alongside the existing rate limiting
from SEC-08.

Added a verifyCaptcha middleware that checks a captchaToken field
submitted with the request against Googles siteverify API using a
server side secret key, rejecting the request before it reaches the
controller if verification fails or the token is missing entirely.

Made the same duplicate route mistake as SEC-03 and SEC-08
initially, where the new captcha protected routes were added below
the old unprotected ones instead of replacing them, so Express kept
matching the old ones first. Fixed by removing the duplicates, and
noting this as a recurring pattern to watch for going forward.

Tested by attempting registration with no captchaToken at all and
confirming it is correctly rejected, then completing the full flow
through the actual frontend with a real captcha checkbox completed
and confirming registration and login both succeed normally.
