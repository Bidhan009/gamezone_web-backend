[SEC-09] Fix: Missing security headers and critical duplicate app instance bug

Found that the server was sending no security related HTTP headers
at all, and was leaking its framework identity through an
X-Powered-By: Express header, giving potential attackers an easy
head start on framework specific exploits.

While testing the fix, discovered a much bigger underlying problem.
index.ts was building its own completely separate Express app from
scratch, re-importing and re-registering all the same routes and
cors settings independently, instead of using the actual app.ts
file. This meant the running server was never using app.ts at all,
so every change made there, including this helmet fix and the
global rate limiter from SEC-08, was silently having zero effect
the whole time, despite the code itself being completely correct.

Fixed the header issue by installing helmet and applying it as the
very first middleware in app.ts. Fixed the deeper issue by
rewriting index.ts to simply import the real app from app.ts and
only handle database connection and starting the server, removing
the duplicate app building code entirely so there is now only one
single source of truth for how the Express app is configured.

Retested after both fixes by checking response headers again, and
confirmed X-Powered-By is gone and a full set of helmet security
headers are now present, including Content-Security-Policy,
X-Frame-Options, and Strict-Transport-Security. Also confirmed as a
side effect that the global rate limiter from SEC-08 is now
actually active too, visible through the RateLimit response
headers, which it was not before this fix.
